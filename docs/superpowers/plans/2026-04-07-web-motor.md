# Web Motor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the Web Motor (C-012) — register pipeline, create 6 agent skill files, add web-standards directive, wire up context maps, and update DB schema.

**Architecture:** Adds a `web` pipeline to the existing PipelineRegistry with 7 steps and 3 gates. Creates 6 agents (WB-L through WB-005). Template-driven: agents select templates, compose content, configure SEO, and validate quality. No custom code generation — works with predefined templates filled with content from Writers Room and assets from Graphic Design.

**Tech Stack:** TypeScript, Drizzle ORM (PostgreSQL), Vitest, Hono

**Spec:** `docs/superpowers/specs/2026-04-07-web-motor-design.md`

```markdown
# Web Standards — Web Motor Directive

## Performance (Core Web Vitals)

| Metric | Target | Measurement |
|--------|--------|-------------|
| LCP (Largest Contentful Paint) | < 2.5s | Largest image or text block in viewport |
| FID (First Input Delay) | < 100ms | Time from first interaction to browser response |
| CLS (Cumulative Layout Shift) | < 0.1 | Visual stability score |

## Accessibility (WCAG 2.1 AA)

| Requirement | Standard |
|-------------|----------|
| Color contrast | Minimum 4.5:1 for normal text, 3:1 for large text |
| Alt text | Required on all non-decorative images |
| Keyboard navigation | All interactive elements must be keyboard accessible |
| Touch targets | Minimum 44x44px on mobile |
| Focus indicators | Visible focus ring on all interactive elements |
| Heading hierarchy | Logical H1 → H2 → H3 order, no skipped levels |
| Language | `lang` attribute on `<html>` element |
| Form labels | Every input must have an associated label |

## SEO Baseline

| Element | Requirement |
|---------|-------------|
| Meta title | < 60 characters, unique per page, includes primary keyword |
| Meta description | 120-160 characters, includes CTA, unique per page |
| H1 | Exactly one per page, includes primary keyword |
| Open Graph | og:title, og:description, og:image required on all pages |
| Schema markup | JSON-LD: minimum WebPage schema, Organization on homepage |
| Sitemap | sitemap.xml auto-generated, submitted to Search Console |
| Robots | robots.txt with sitemap reference |
| Canonical | rel="canonical" on all pages |

## Images

| Requirement | Standard |
|-------------|----------|
| Format | WebP with JPEG/PNG fallback |
| Lazy loading | All images below the fold |
| Max size | 200KB per image after compression |
| Responsive | srcset with 1x, 2x sizes |
| Aspect ratio | Set width and height attributes to prevent CLS |

## Mobile

| Requirement | Standard |
|-------------|----------|
| Approach | Mobile-first responsive |
| Breakpoints | 375px (mobile), 768px (tablet), 1280px (desktop) |
| Touch targets | Minimum 44x44px |
| No horizontal scroll | Content must fit viewport width |
| Viewport meta | `<meta name="viewport" content="width=device-width, initial-scale=1">` |

## Forms

| Requirement | Standard |
|-------------|----------|
| Validation | Client-side + server-side |
| CSRF | Protection on all forms |
| Anti-spam | Honeypot field (no visible CAPTCHA) |
| Error messages | Inline, specific, helpful |
| Success state | Clear confirmation message |
```

```markdown
# Identity

You are the **Information Architect** — you structure information so users find what they need. You design sitemaps, navigation, and content hierarchies that are intuitive and scalable.

# Role in Pipeline

## wb_architecture
- Design sitemap: page hierarchy with URL slugs
- Define navigation: primary (5-7 items max), secondary, footer
- Map template components to each page
- Define form fields for lead capture
- Output as structured JSON

# Rules

1. Navigation depth: max 2 levels for SMB sites, 3 for corporate
2. Every page must be reachable in 3 clicks from homepage
3. URL slugs: lowercase, hyphenated, descriptive (no /page1, /page2)
4. Homepage must clearly communicate what the business does
```

```markdown
# Identity

You are the **QA Tester** — you catch every issue before the site goes live. You validate responsive design, accessibility, performance, and functionality.

# Role in Pipeline

## wb_qa
- Responsive: check at 375px, 768px, 1280px
- Accessibility: WCAG 2.1 AA audit (contrast, keyboard, alt text, labels)
- Performance: Core Web Vitals targets (LCP <2.5s, FID <100ms, CLS <0.1)

- Forms: test submission, validation, error states

2. Accessibility is not optional — WCAG 2.1 AA is the minimum
3. Performance issues must include specific remediation steps
4. Forms must be tested with valid and invalid inputs
```
