## 1. Context

Platform Intelligence (PI) is criteria.agency's accumulated cross-client knowledge — anonymized, aggregated, and shared with all agents. It is the mechanism by which the platform gets smarter with every campaign, every client, and every market interaction.

Without PI, every client starts from zero. The Strategist proposes based on frameworks alone. The Creative Director has no empirical basis for format recommendations. Budget calculations rely on generic industry averages. With PI, the platform compounds its intelligence: the 500th campaign benefits from the learnings of the first 499.

PI was referenced extensively across prior specs (Strategist Motor Design §4.1-4.5, Brand Builder Motor Design §3.2, Business Model Design) but deferred as a separate spec per DEC-094. This document defines the complete design.

### Position in the platform

| Attribute | Value |
|-----------|-------|
| Category | Infrastructure (shared) |
| Type | System function (DEC-064 taxonomy) — not an agent |
| Mode | Continuous — always available, batch-updated |
| Output | Benchmarks, patterns, rankings, trend data |
| Consumers | All agents with appropriate access level |
| Writers | Campaign Learning (Strategist), Distribution agents, Brand Guardian, Channel Manager, Brand Builder, Listeners |

### Key decisions made in this spec

| Decision | ID | Choice |
|----------|----|--------|
| Three writer types | DEC-102 | Learning Records (Strategist), Operational Signals (Distribution/Guardian/Channel Manager), Structural Patterns (Brand Builder/Listeners) |
| Unified repository | DEC-103 | Single repository with unified API. Responses include metadata (type, confidence, source, temporal window, match level) |
| Dimension model | DEC-104 | Context (industry, region, size) × Execution (channel, format, funnel stage, messaging) × Result (performance metrics, investment ranges) |
| Hierarchical fallback | DEC-105 | When N < K at specific level, system widens temporal window, then ascends dimension hierarchy. Hardcoded in PI, not in consuming agents |
| Cold start three layers | DEC-106 | industry_benchmark (public data, day 1) → platform_early (beta testers) → platform (real N). Source quality always disclosed |
| K-anonymity thresholds | DEC-107 | K=5 default, K=3 for operational signals. Never below 3 |
| Additional privacy protections | DEC-108 | Ranges instead of exact values at low K, outlier suppression (P10-P90), max 30% contribution per client |
| No opt-out | DEC-109 | Contributing to PI is part of the platform's social contract. All benefit because all contribute |
| Differentiated decay | DEC-110 | Operational signals: 3-month half-life. Learning records: 12-month half-life. Structural patterns: recalculated periodically, not decayed |
| Geographic hierarchy | DEC-111 | City → Country → Subregion → LATAM. Region = campaign target market, not client domicile |
| PI is a system function | DEC-112 | Not an agent. Aggregates and serves data. Never interprets or recommends |
| Two query modes | DEC-113 | Benchmark query ("what is the standard?") returns values. Pattern query ("what works?") returns rankings/distributions |

| Public KPIs | DEC-116 | Volume metrics (scale proof) + Efficacy metrics (intelligence proof). Three surfaces: landing page, Brújula, exportable reports |

| Listeners excluded from PI | DEC-120 | Listeners observe external world. PI aggregates internal world. Strategist synthesizes both. Separation prevents circular bias (extends DEC-058) |

## 2. Core Concept: Three Types of Intelligence

Platform Intelligence is not a single data stream. Three distinct types of data enter the system, each from different writers, with different characteristics, and at different confidence levels.

### 2.1 Learning Records

**Writers:** Strategist (via Campaign Learning skill)

**When produced:** After a campaign closes (trigger 16 in Strategist spec) or during pre-planning review (trigger 17).

**What they contain:** Causal knowledge — "we did X, and Y happened." A Learning Record captures the full arc of a campaign: what was planned, what was executed, what was adjusted, and what resulted.

**Example (anonymized):**

| Field | Value |
|-------|-------|
| Industry | Restaurants |
| Region | LATAM, urban market |
| Funnel stage | Awareness |
| Channel | Meta (Instagram Reels) |
| Format | Short video (<30s) |
| Messaging type | Emotional |
| Audience category | 25-35, food enthusiasts |
| Investment range | $500-1,000 |
| Result | CTR 3.2%, CPM $4.50, engagement rate 8.1% |
| Comparison | Emotional vs rational in same campaign: 1.4:1 ratio favoring emotional |

**What is NOT included:** Client name, brand name, specific copy or creative, exact budget (range only), custom audience definition, competitive positioning.

**Confidence:** Highest. Based on verified campaign results with known inputs and outputs.

**Decay:** 12-month half-life. Strategic patterns persist but evolve.

### 2.2 Operational Signals

**Writers:** Paid Media Operator, Owned Channels Operator, Brand Guardian, Channel Manager

**When produced:** As a side effect of daily operations. Aggregated in weekly batch, not real-time.

**What they contain:** Correlation data — "we observe Z across N clients." Not tied to specific campaigns — these are operational patterns that emerge from the platform working.

**Examples:**
- Paid Media Operator: Average CPM by channel × industry × region (updated with each execution)
- Brand Guardian: Rejection rate by error type × industry (tone, visual, message inconsistency)
- Channel Manager: Format engagement rates by channel (updated with each execution)
- Owned Channels Operator: Best posting times by audience category × channel

**Confidence:** Medium. Correlational, not causal. Useful for benchmarking and planning, not for strategic decisions in isolation.

**Decay:** 3-month half-life. Operational metrics (costs, engagement rates) shift rapidly with platform algorithm changes and market dynamics.

### 2.3 Structural Patterns

**Writers:** Brand Builder (from Brand DNA analysis across clients), Listeners (from market observation)

**When produced:** Periodically recalculated (monthly). Not event-driven.

**What they contain:** Market-level intelligence that emerges from the client base, not from campaigns.

**Examples:**
- Brand Builder: "60% of ecommerce clients in LATAM define their differentiator as price or shipping" → commoditized market signal
- Competitive Listener: "3 of 5 fitness industry competitors are shifting toward educational content" → industry trend
- Culture Listener: "The term 'sustainability' grew 40% in mentions in fashion industry in Q1" → cultural shift

**Confidence:** Variable. Depends on N and recency. Market-level patterns are valuable but require sufficient client base to be statistically meaningful.

**Decay:** No temporal decay. Recalculated from current state of active Brand DNAs and Listener data. The pattern reflects what's true now, not what was true historically.

## 3. Dimension Model

### Dimensions

All data in PI is tagged with dimensions that determine how it can be queried and aggregated.

**Context dimensions (the "where"):**

| Dimension | Values | Source |
|-----------|--------|--------|
| Industry | Restaurants, ecommerce, fitness, SaaS, professional services, etc. | Client's Mi Negocio |
| Region | City, Country, Subregion, LATAM (hierarchical — see §5) | Campaign target market |
| Business size | Proxy: client tier (Starter/Pro/Agency) or revenue range | Client's Mi Negocio |

**Execution dimensions (the "what"):**

| Dimension | Values | Source |
|-----------|--------|--------|
| Channel | Meta, Google, TikTok, LinkedIn, Email, SEO, etc. | Campaign activation |
| Format | Short video, carousel, article, email, reel, story, etc. | Piece produced |
| Funnel stage | Awareness, Consideration, Conversion, Retention | Activation position in Funnel Matrix |
| Messaging type | Emotional, rational, educational, promotional, testimonial | Creative version classification |

**Result dimensions (the "how much"):**

| Dimension | Values | Notes |
|-----------|--------|-------|
| Performance metrics | CTR, CPM, CPC, ROAS, engagement rate, conversion rate, completion rate | Numeric, aggregated |
| Investment range | Budget brackets, not exact figures | Anonymized by design |

### Hierarchical fallback

Every dimension combination divides the data. With few clients, most specific combinations will have insufficient N. The fallback system resolves this transparently.

**Query resolution order:**

1. Exact match with recent data (last 90 days)
2. Exact match with expanded temporal window (up to 12 months)
3. Widen one dimension level (e.g., country → subregion)
4. Continue widening until N ≥ K
5. Final fallback: industry_benchmark layer (always available)

Each step down reduces the reported confidence level. The consuming agent always knows what level of match it received.

**The fallback is hardcoded in PI, not in the consuming agents.** An agent sends a query with maximum specificity. PI returns the best available match with full metadata. The agent does not need to know how the fallback works internally.

## 4. Anonymization and Privacy

### Principle

DEC-095 (extending DEC-083): **the environment is shareable, the identity is not.** What describes the market (costs, performance patterns, trends) can be shared. What describes a specific brand (strategy, positioning, budget, competitive approach) cannot.

### K-Anonymity

An aggregate is only served if at least K distinct clients contributed data to that dimension combination.

| Data type | Minimum K | Rationale |
|-----------|-----------|-----------|
| Learning Records | 5 | Campaign-level data is the most potentially identifying |
| Operational Signals | 3 | Less sensitive — operational metrics like CPM are market-level, not strategic |
| Structural Patterns | 5 | Brand DNA patterns could reveal positioning strategies |

**Never below K=3 for any data type, under any circumstance.**

When N < K at the queried level, PI ascends the fallback hierarchy rather than serving the insufficiently anonymized aggregate.

### Additional protections

**1. Ranges instead of exact values at low K (3-7).**

When K is between 3-7, result values are served as ranges, not exact numbers. "CAC is in the $10-15 range" rather than "CAC is $12.43." When K > 10, exact aggregates can be served because individual contributions are sufficiently diluted.

**2. Outlier suppression.**

Before aggregation, outliers are trimmed using P10-P90 percentiles. This prevents extreme values from both distorting the aggregate and being potentially identifiable. ("The one with the 15x ROAS must be Brand X.")

**3. Maximum contribution per client: 30%.**

No single client can represent more than 30% of the data in any aggregate. If K=5 but one client contributed 80 campaigns and the other 4 contributed 5 each, the aggregate is reweighted so each client contributes equitably to the mean.

### No opt-out (DEC-109)

Contributing data to Platform Intelligence is part of the platform's social contract. All clients benefit because all contribute. This is the Waze model: your location data feeds the traffic map that benefits you.

This must be communicated transparently during onboarding and in terms of service. The value exchange is explicit: "Your anonymized campaign data contributes to industry benchmarks. In return, you receive benchmarks from all clients in your industry."

### Competitors on the platform

When two direct competitors are both clients, both receive the same industry benchmarks — benchmarks that include each other's anonymized data. This is a **feature, not a bug:**

- Both receive identical benchmarks. Neither has an advantage.
- The benchmark says "industry average" — never "your competitor does X."
- This mirrors how consulting firms (McKinsey, BCG) publish industry benchmarks that include all participants.
- Competitive advantage comes from what you do with the benchmark (Client Intelligence + Strategist decisions), not the benchmark itself. Those are private.

## 5. Geographic Hierarchy

### Four levels

| Level | Examples | When useful |
|-------|----------|-------------|
| City | Bogotá, Ciudad de Panamá, CDMX | Large markets with sufficient N |
| Country | Colombia, Panamá, México | Primary aggregation level |
| Subregion | Centroamérica + Caribe, Andina, Cono Sur, México + US Hispanic | Groups markets with similar ad costs and consumer behavior |
| LATAM | Everything | Final fallback before industry_benchmark |

### Subregion rationale

Subregions are not arbitrary — they group markets with similar advertising costs, consumer behavior, and media landscape:

- **Centroamérica + Caribe:** Similar CPMs, shared media platforms, comparable market sizes
- **Andina:** Colombia, Ecuador, Perú, Venezuela — shared cultural and economic patterns
- **Cono Sur:** Argentina, Chile, Uruguay — higher purchasing power, different media mix
- **México + US Hispanic:** Mexico has sufficient volume for its own subregion; US Hispanic is a market many LATAM clients expand into

### Region attribution

The region of a data point is the **campaign's target market**, not the client's domicile. A Panamanian business selling online to all of Central America contributes campaign data to "Centroamérica," not "Panamá." This prevents distortion of small local markets and accurately reflects where the marketing activity actually occurred.

## 6. Temporal Decay

### Principle

Not all data ages equally. Operational costs shift monthly. Strategic patterns persist for years. The decay model reflects this.

### By data type

| Type | Decay model | Half-life | Rationale |
|------|-------------|-----------|-----------|
| Operational Signals | Exponential | 3 months | CPM, CPC, engagement rates change rapidly with platform algorithm updates and market dynamics |
| Learning Records | Exponential | 12 months | Campaign-level patterns are more stable but still evolve |
| Structural Patterns | Periodic recalculation | N/A | Calculated from current Brand DNA state and Listener data; reflects present reality, not history |

### Implementation

Decay is implemented as a **weight at aggregation time**, not as data deletion. A 6-month-old operational signal weighs 25% of a current one. A 2-year-old learning record weighs ~6%. Data is never deleted — it becomes naturally irrelevant.

### Temporal windows in responses

Every PI response includes the temporal window of its data:

- "CTR average: 2.8% (last 90 days, N=23 campaigns)" — fresh, reliable
- "ROAS average: 3.1x (last 12 months, N=8 campaigns)" — expanded window due to insufficient recent N
- "Messaging pattern: emotional outperforms rational 2.1:1 (45 campaigns over 18 months)" — stable learning

The fallback system expands temporal windows **before** ascending dimension levels. This preserves specificity at the cost of recency — usually the better trade-off.

## 7. Cold Start

### The problem

Day 1: zero clients, zero campaigns, zero data. A client registers. The Strategist needs CAC benchmarks (DEC-101). Platform Intelligence is empty.

### Three-layer solution

| Layer | Source | Available when | Confidence label | Maintenance |
|-------|--------|---------------|-----------------|-------------|
| `industry_benchmark` | Public data: Meta Business Suite, Google Ads industry averages, HubSpot, Statista | Day 1 | Low — "industry reference" | Updated quarterly from public sources |
| `platform_early` | CriteriaFilms + 3-5 beta testers from different industries | Pre-launch | Medium — "early platform data" | Grows into `platform` naturally |
| `platform` | Real aggregated data from N ≥ K clients | Post-threshold | High — "platform data" | Continuous via Campaign Learning and operational signals |

### How it works

The fallback hierarchy naturally handles cold start. When an agent queries PI:

1. Search for `platform` data at the requested specificity → if N ≥ K, serve it
2. If insufficient, check `platform_early` data → serve with medium confidence
3. If insufficient, fall back to `industry_benchmark` → serve with low confidence and explicit source disclosure

The response always qualifies the source: "Based on 47 campaigns on our platform" vs "Based on early platform data (12 campaigns)" vs "Based on industry benchmarks (external source)."

### Limitations of industry_benchmark layer

- Typically global or US/EU-centric, rarely LATAM-specific
- Published annually — ages quickly
- Low granularity ("retail" ≠ "sportswear ecommerce in Bogotá")
- Available to everyone — provides no competitive advantage

These limitations are acceptable because:
- The Strategist is honest about the source: "This is a market reference, not proprietary data"
- The first campaigns are explicitly positioned as exploratory (Strategist spec §5, new client section)
- The `industry_benchmark` layer becomes progressively less used as `platform` data accumulates

### The moat narrative

The transition from public benchmarks to proprietary data IS the moat being built in real time. This can be tracked as a platform health metric:

- Month 1: "95% of benchmarks sourced from industry references"
- Month 6: "60% proprietary platform data"
- Year 1: "90% proprietary — benchmarks cover 12 industries in 6 LATAM markets"

## 8. Internal API

### Design principles

PI is a **system function** (per DEC-064 taxonomy). It processes queries and returns data. It never interprets, recommends, or makes decisions. The consuming agent is responsible for all interpretation.

### Two query modes

#### Mode 1 — Benchmark Query: "What is the standard?"

The agent wants a reference value for comparison or planning.

**Use cases:**
- Strategist (Planning): "What is the expected CAC for ecommerce in Mexico, Meta channel?"
- Financial Agent: "Average ROAS for my industry and investment range?"
- Strategist (Campaign Design): "Expected CTR for short video in awareness, audience 25-35, LATAM?"

**Query structure:**
- Filter dimensions: industry, region, channel, format, funnel stage, messaging type, investment range
- Requested metric: CTR, CPM, CAC, ROAS, engagement rate, etc.
- The agent sends what it knows. PI returns the best match.

**Response structure:**
- Value (or range if K is low)
- N (contributing clients)
- Source (`platform` / `platform_early` / `industry_benchmark`)
- Confidence (`high` / `medium` / `low`)
- Match level (exact / widened on X dimension)
- Temporal window (last 90 days / 12 months / etc.)
- Trend (rising / stable / declining — if sufficient history exists)

#### Mode 2 — Pattern Query: "What works?"

The agent wants a pattern or ranking, not a single value.

**Use cases:**
- Strategist (Campaign Design): "What messaging type works best in awareness for my industry?"
- Channel Manager: "Top 3 channels by ROAS for SaaS in LATAM?"
- Creative Director: "Which formats have the best completion rate on TikTok?"
- Brand Builder (Layer 2): "Most common differentiators in my industry?" (to flag commoditization)

**Response structure:**
- Ordered list of options with relative values (e.g., "emotional > educational > rational, 2.8:1.4:1")
- N per option (not all have equal support)
- Same metadata: confidence, source, temporal window

### Three hard restrictions

1. **PI never recommends.** It serves data and patterns. "Emotional outperforms rational 2x" is data. "You should use emotional messaging" is a recommendation — that's the Strategist's job.

2. **PI never crosses the identity barrier.** No query can request data from a specific client or filter such that only one client remains. If a query result has N < K, the system ascends the fallback hierarchy. Never serves the point data.

3. **PI never serves real-time data from active campaigns.** Operational signals are aggregated in weekly batch. This prevents anyone from monitoring incremental changes to infer a competitor's activity. "The average CPM in my industry rose $0.50 this week" could mean a competitor just launched an aggressive campaign — and at low N, that's nearly identifiable.

### Access levels

| Access level | Agents | What they can query |
|-------------|--------|-------------------|
| **Full** (benchmark + pattern) | Strategist, Financial Agent, Brand Builder (Layer 2+) | All query modes, all dimensions |
| **Pattern only** | Creative Director, Channel Manager, Media Scout | Pattern queries only. No competitive numerical benchmarks |
| **Benchmark only** | Analyst (DEC-123) | Benchmark queries only. Contextualizes client data against industry averages. No pattern access — strategic interpretation is Strategist territory |
| **Operational** | Paid Media Operator, Owned Channels Operator | Aggregated operational metrics relevant to their channels only |
| **No access** | Brand Guardian | Validates against Brand DNA, not market benchmarks. Differentiation is not an error — comparing to industry norms could undermine brand uniqueness |

### Visibility by client tier

Agent access is always full (the Strategist always uses PI to make better recommendations regardless of tier). What varies is what the **client sees directly**:

| Tier | Client-facing visibility |
|------|------------------------|
| Starter | Generic benchmarks (industry × LATAM). No regional or sub-industry granularity |
| Pro | Full benchmarks (industry × region × channel). Pattern queries visible in Brújula and Copilot |
| Agency | Pro + benchmarks in white-label reports + cross-industry trend access |

## 9. Public KPIs

### Purpose

DEC-093: Platform Intelligence is also exposed as public KPIs proving criteria.agency's efficacy. Dual purpose: marketing (convince prospects) and moat (demonstrate accumulated intelligence competitors cannot replicate).

### Three surfaces

**1. Landing page (public).**

Static numbers updated quarterly. What a prospect sees before registering.

**2. Inside the platform (Brújula).**

Contextualized benchmarks for registered clients. "Your ROAS is 2.8x. Your industry average on the platform is 3.1x." Already designed — served by PI's internal API and surfaced via Copilot or Brújula.

**3. Exportable reports.**

Pro/Agency clients include PI benchmarks in reports for stakeholders. "Our CPM of $4.20 is 18% below the industry average ($5.10)." Makes the client's report more professional and anchors criteria.agency's value.

### What is exposed publicly

**Volume KPIs (prove scale):**
- Total campaigns executed on the platform
- Managed ad spend (range, not exact)
- Active clients by industry (only when N > threshold to avoid revealing weak verticals)
- Countries with presence

**Efficacy KPIs (prove intelligence):**
- Average ROAS by industry ("our ecommerce clients achieve 3.2x ROAS")
- Improvement over time: "on average, a client's third campaign performs 40% better than their first" — proves PI works, that the platform learns
- Recommendation adoption rate: "73% of Strategist-proposed campaigns are approved without major changes" — proves client trust in the AI
- Cost benchmarking: "average CPM managed by criteria.agency is 22% below industry benchmark" — proves operational optimization

### What is never exposed publicly

- Individual client data
- Granular benchmarks by dimension combination (that's the product — giving it away removes the incentive to be a client)
- Data from industries with low N (would reveal weak verticals)
- Negative data without context (failed campaigns, poor-ROAS industries) — not because they're hidden, but because the public lacks context to interpret them

### Platform Intelligence Report (DEC-117)

A quarterly automated publication — criteria.agency's own owned media asset.

**What it contains:**
- Headline efficacy KPIs for the quarter
- Trends by industry (which industries grew, which channels emerged)
- The platform data maturity narrative: "X% of our benchmarks are now proprietary platform data"
- Selected anonymized case patterns ("campaigns using emotional messaging in awareness outperformed rational by 2.1:1 across 45 campaigns")

**Funnel applications:**
- **Awareness:** Published on blog, shared on social media, picked up by industry media
- **Consideration:** Prospect reads the report and thinks "I want access to this data"
- **Conversion:** Sales material — "our platform has X campaigns of data in your industry"

**Production:** Fully automated. PI provides the data. Strategist (for criteria.agency's own account) provides narrative structure. Writer produces copy. Generated as owned media through criteria.agency's own motors. The founder approves the final output.

## 10. Token Cost Model

### PI queries are free (DEC-118)

Consulting PI does not consume tokens. It is part of the "observe" layer defined in DEC-100:

| Layer | Cost | Examples |
|-------|------|---------|
| Base configuration | Included in tier | Mi Negocio, Brand DNA |
| **Passive observation** | **Included in tier** | **Listeners, Analyst dashboards, Brand Health Score, PI queries** |
| Strategic intelligence | Tokens | Strategist outputs (diagnoses, plans, briefs, optimizations) |
| Asset production | Tokens | Creation motor outputs (video, design, copy) |

**Rationale:** Charging for PI queries would cause agents to query less, degrading recommendation quality. PI is a quality multiplier for everything else — it should be free to maximize its impact.

This also reinforces the no-opt-out social contract: "Your data contributes to PI, and in return you query it freely."

### Independence principle

PI aggregates the **internal world** (what happens inside the platform). Listeners observe the **external world** (what happens in the market). The Strategist is the synthesis point — the only agent that receives both internal benchmarks and external intelligence and makes decisions from both.

This separation prevents circular bias: if Listeners consulted PI, they might prioritize signals that PI validates and ignore signals that contradict PI — exactly the bias DEC-058 was designed to prevent.

## 13. Implementation Notes

### Priority

PI is infrastructure that enhances every other motor. The cold start design (§7) means it provides value from day 1 even without real platform data. Implementation can be phased:

### Recommended build order

1. `industry_benchmark` layer — seed with public data for core industries (restaurants, ecommerce, professional services, fitness, SaaS)
2. Benchmark query API — the simplest query mode, serves cold start data
3. Learning Record schema + Campaign Learning write path (after Strategist motor)
4. Fallback hierarchy engine
5. Pattern query API
6. Operational Signal write paths (after Distribution agents)
7. K-anonymity enforcement + privacy protections
8. Structural Pattern calculation (after Brand Builder + Listeners)
9. Public KPI dashboard
10. PI Report automation
11. Tier-based visibility filtering

### Model considerations

- PI is a system function — no LLM needed for queries. Standard database aggregation.
- The PI Report is the exception: requires Strategist + Writer for narrative production.
- Trend calculation (rising/stable/declining) is statistical, not AI — linear regression over temporal windows.

## 14. Resolved Design Questions

### 14.1 Why PI is not an agent

PI processes queries and aggregates data. It makes no decisions. Creating an agent for PI would be like creating an agent for the database — unnecessary intelligence where a system function suffices. The intelligence is in the agents that query PI and interpret its responses.

### 14.2 Why Brand Guardian has no PI access

The Brand Guardian validates that outputs are consistent with the client's Brand DNA — their specific identity, tone, visual system. If the Brand Guardian had access to industry benchmarks, it could develop a tendency to flag outputs that deviate from industry norms. But deviation from industry norms is often exactly what good branding is. A rebellious brand should not be pulled toward the industry average. The Brand Guardian's job is to protect what makes the brand unique, not to make it average.

### 14.3 Why Listeners don't read PI

DEC-058 established independence between Listeners and the Strategist to prevent circular bias. The same logic extends to PI. If Listeners consulted PI before reporting, they might weight observations that align with existing platform patterns and downweight novel signals. The whole point of Listeners is to detect what's new and different — including things that contradict current PI patterns.

### 14.4 Competitive scenarios

**Two competitors, same industry, same market.**
Both receive identical benchmarks. The benchmark includes both their data (anonymized). Neither can identify the other's contribution. The competitive advantage is in Client Intelligence (private) and Strategist decisions (private).

**Small industry with N < K.**
PI ascends the fallback hierarchy: broader industry category → broader region → LATAM. The response discloses that the benchmark is not industry-specific. The Strategist adjusts its confidence accordingly.

**A dominant client (>30% of data).**
The 30% contribution cap ensures no single client skews the aggregate. Their surplus data is down-weighted so the benchmark reflects the industry, not one player.

### 14.5 The PI Report as owned media

The quarterly PI Report is criteria.agency eating its own dog food. It's produced by the platform's own motors (Strategist for narrative direction, Writer for copy), approved by the founder, and published as owned media. It serves three funnel stages simultaneously (awareness through industry visibility, consideration through intelligence proof, conversion through data credibility). It also demonstrates the platform maturity arc as benchmarks transition from external to proprietary sources.
